# 招标文件拆解（W18，完成里程碑 M3）

对应开发方案 4.3 应用 B：招标 / 询价文件 → 关键信息与时间节点 → 需求矩阵（★实质性、废标条款单独标出）→ 偏离表 → 评分点 → 资料清单 → 技术规格转工程项目（应用 A）→ 提交投标。

## 一条完整的流程

```
文档解析页：上传招标文件（kind=tender）→ 核对字段（每个字段带页码原文）
        │  投标截止时间必须人工确认或改正（错了就是丢标）
        ▼
POST /v1/tenders                     sales.tender_registered 事件（证据 = 字段页码与原文）
        │                            按澄清截止、投标截止生成提醒待办（收件箱），并自动做第一次拆解
        ▼
GET  /v1/tenders/{id}                关键信息、提醒、拆解结果、风险、事件历史
PATCH /v1/tender-analyses/{a}/items/{条款}      响应 / 负责人 / 状态（已响应、接受偏离、不适用）/ 人工改偏离
PATCH /v1/tender-analyses/{a}/documents/{资料}  资料库没有的资料线下办好后标“已备齐”
POST /v1/tenders/{id}/eng-project    技术规格 → 工程项目（选材、传热、BOM、报价走 docs/engineering.md）
POST /v1/tenders/{id}/analyze        重新拆解（补遗、资料库或知识库变了）：新版本，人工处理结果按条款保留
        ▼
POST /v1/tender-analyses/{a}/submit  sales.tender_submitted 事件 → policy.yaml：销售负责人确认、
        │                            50 万以上加总经理、★条款负偏离是红线（直接拒绝）
        ▼
POST /v1/tenders/{id}/close          中标 / 未中标 / 放弃（中标后按工程报价登记合同，见 docs/orders.md）
GET  /v1/tender-analyses/{a}/export  Excel：需求矩阵、偏离表、资料清单、评分点
```

网页：`/app/tender.html`。IM：「招标」列出进行中的项目（按截止时间），「招标 编号」看一个项目的进度和风险。

## 拆解怎么做（`fos/tender/decompose.py`，确定性代码，零模型成本）

| 步骤 | 做法 |
|---|---|
| 结构识别 | 标题行（Markdown `#`、“第 X 章”）里出现 `tender.yaml` 的章节关键词就归类：招标公告、投标人须知、评标办法、合同条款、技术规格书、工程量清单、投标文件格式 |
| 条款拆解 | 逐行（表格逐行）切条款；带 ★ / ▲ / “必须”“不得”“应”“提供”“不低于”等的才算要求（“供应商”“须知”里的字不算）。级别：★ 实质性 / ▲ 重要 / 必须 / 一般；★ 和含“废标、无效投标、否决”的标“可能废标”。类别按关键词，没命中按章节默认。条款 id = 章节 + 原文的哈希，重新拆解时用它对上人工处理结果 |
| 评分点 | 评标办法章节里带“N 分”的句子；“最多 10 分”取上限；提到业绩、检测报告、证书的对上资料 |
| 资料清单 | 原文提到营业执照、ISO9001、检测报告、业绩、投标函、授权书、保证金……就列出；读出“近一年内”“不少于 2 项”；和资质资料库（`credential` 对象）对上：已有 / 过期（有效期早于投标截止）/ 超过时效 / 数量不够 / 缺失 / 按格式编制 |
| 偏离 | 从条款读“分类温度不得低于 1400℃”“质保期不少于 12 个月”“交货期 45 日历天”，换算单位后和我方能力比较：无偏离 / 正偏离 / 负偏离 / 待确认。我方能力：分类温度取知识库（转了工程项目且已发布报价的，取报价方案里最差的产品）；质保期、交货期取配置里的承诺值；检测报告时效取资料库最新一份的签发日期 |

★ 条款只认原文标记、宁多勿漏（方案 7 章指标：★召回率 ≥ 95%）。模型不参与判断；以后接模型只做补充（例如给没有标记的条款建议类别），不改原文与页码。

## 提交前的硬检查（代码）与审批（policy.yaml）

代码：★ / ▲ / 必须 / 可能废标的条款全部处理过；资料清单没有未处理的缺失或过期；不是模拟数据；拆解之后招标项目没改过；没过截止时间。
审批与红线在 `tenants/luneng/policy.yaml`（占位值，待试点确认）：提交投标需销售负责人确认；投标报价 ≥ 50 万加总经理；`star_negative > 0`（★条款负偏离）直接拒绝。审批通过后以申请人身份入账。

## 截止提醒

- 登记时按澄清截止、投标截止给负责人生成待办（`/v1/inbox` 里能看到）；截止时间改了旧待办作废、重新生成；放弃投标时关掉。
- `fos channels run` 进程按 `tender.yaml` 的 `reminders.offsets_hours`（默认 72 / 24 / 3 小时）推 IM 给负责人和 `notify_roles`；每个时间点只推一次。

## 配置与数据（都不用改代码）

| 内容 | 放在哪 |
|---|---|
| 章节关键词、条款标记、类别关键词、建议负责人、我方能力、资料清单、提醒时间 | `packs/refractory/tender.yaml`，租户可用 `tenants/<id>/tender.yaml` 按段覆盖 |
| 招标文件字段 | `packs/refractory/extraction/tender.yaml`；技术规格字段用 `include` 借技术文件 Schema 的同名字段（叫法只维护一处） |
| 资质与资料 | 账本对象 `credential`：`kb.credential_registered` / `kb.credential_updated`（`kb.credential:write`）；`GET /v1/credentials` 查看 |
| 演示资料库 | `fos eng-demo` 同时写入 `packs/refractory/tender/sample_credentials.yaml`（模拟数据：只能演示，不能提交投标、不能导出） |

权限：招标项目在 `sales` 域（`sales.tender:read / write`），工程技术角色也给了读写（方案 5 章：工程师助理负责招标拆解）；转工程项目还需要 `eng.project:write`。

## 待现场确认（占位值）

- 我方承诺：质保期 12 个月、交货期 30 天（`tender.yaml` capabilities）；
- 审批：投标报价 50 万以上加总经理；提醒推给谁（默认销售负责人）、提前多久；
- 真实资质资料（营业执照、ISO 证书、检测报告、业绩合同）需要登记进资料库；
- 用六安绿能拿到的真实招标文件补充章节、类别、资料关键词。
