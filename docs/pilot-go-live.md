# 试点上线支持（W13）

W13 是“缓冲与试点上线支持”：录单（M1）和工程方案（M2）两条线已经能用，这一周补齐**上线那几天真正会卡住的事**。

| 卡点 | 做了什么 | 入口 |
|---|---|---|
| 系统里没有主数据，录单查不到物料、产品、窑炉 | 主数据 Excel 批量导入：按本体生成模板 → 预览 → 一次入账 | 网页 `/app/pilot.html`、`fos import-template` / `fos import`、`/v1/import/*` |
| 管理者不知道每天录了什么、哪里有问题 | 生产日报：账本确定性统计 + 告警 + 待处理事项；IM 里发“日报”，每天定点推送 | IM「日报」、`fos daily-report`、`/v1/reports/daily` |
| 不知道离上线还差什么 | 上线检查：配置、数据库、模型 / OCR 模式、IM、用户绑定、审批人、主数据、日报收报人逐项列出 | `fos pilot-check <租户>` |

全部不调用大模型，也不需要百炼 Key。

## 上线步骤（建议顺序）

```bash
fos pilot-check luneng                       # 1. 先看差什么（只读）
fos create-user luneng gm 张总 --roles gm      # 2. 建账号：审批规则用到的角色（gm、sales_lead）必须有人
fos bind-im luneng gm dingtalk <钉钉 userid>    #    绑定 IM，工人拍照、审批卡片、日报都靠它
fos import-template luneng 主数据.xlsx          # 3. 生成模板，交给现场填（或在网页“试点上线”下载）
fos import luneng 主数据.xlsx                   #    预览：逐行列出新增 / 已存在 / 错误，不写入
fos import luneng 主数据.xlsx --commit          #    没有错误才入账
# 4. tenants/luneng/tenant.yaml 填 reports.daily.to（收报人登录名），重启 fos channels run
fos pilot-check luneng                       # 5. 再查一遍，✗ 清零即可试运行
```

## 主数据导入

- **模板由本体生成**：`packs/<pack>/import.yaml` 声明有哪些工作表（供应商、客户、物料、产品、设备、窑炉）、每张表追加哪些事件、按哪个属性判断“已存在”（名称、牌号）。列就是事件字段的中文名，必填带 `*`，表头批注写着填写说明（枚举的中文选项、单位、引用填什么）。加一类主数据 = 在 import.yaml 加一行，不写 Python。
- **一行 = 一个对象**：先追加创建事件，再追加这一行填了字段的更新事件（产品的“类别、分类温度、体积密度”就是 `sales.product_specified`）。
- **引用**：窑炉的“对应设备台账”填设备名称或编号，可以引用同一份文件里前面表的行（按 import.yaml 的顺序导入，不按文件里的顺序）。
- **转换都是确定性的**：“1,350”→ 1350；“2026年11月7日”“2026/11/7”→ 日期；不带时区的时间按工厂时区；“是 / 否”；枚举中文和英文代码都认。
- **全有或全无**：预览和入账走同一条路径——整份文件在一个保存点里逐行 `Ledger.append()`，预览最后回滚；入账只在没有任何错误时提交，否则一条也不写。
- **治理照常**：以导入人身份和权限写入（需要 `platform.import:write`，默认只有 admin；每个事件自己的写权限也要有），本体校验、引用检查、Policy 全部生效。命中审批规则的行报错，请单独提交。
- **证据**：原件按内容存档，每个事件的证据是 `blob://<租户>/<sha256>` + “工作表 第 N 行”。
- **可重复执行**：已存在的（编号相同，或 key 属性相同）跳过；幂等键 `import:<表>:<key>`。只看真实数据，演示（模拟）数据不会挡住真实导入。

## 生产日报

- **统计项在 `packs/<pack>/reports.yaml`**：每项写统计哪些事件、按什么度量（计数或数值字段）、单位字段、分组字段。数值先取事件里的值，没有再取对象当前值；不同单位分开合计，不混加。租户可在 `tenants/<id>/reports.yaml` 整体替换。
- **日期**：按业务发生时间（`occurred_at`）落在工厂时区的哪一天。账本时间统一存 UTC（这次顺带让 SQLite 和 PostgreSQL 一致）。
- **告警**沿用 `trace.yaml` 的 alerts（检验不合格、来料判退 / 未检、烧成偏差……），作用在当天有事件的对象上。
- **待处理**：待审批、未确认的录单卡片、未完成待办的数量，提醒“还有什么卡着”。
- **按人出报告**：只含收报人有读权限的统计项和告警（工人看不到仓库和质检）。
- **模拟与真实不混算**：当天有真实事件就只统计真实数据；只有模拟事件时整份日报标“模拟数据”。
- **IM**：发「日报」「昨天日报」「日报 11-06」「日报 2026-11-06」走 Fast Path，直接回卡片，不经 Router、不调模型。
- **定时推送**：`tenant.yaml` 里 `reports.daily: {at: "19:00", to: [gm, ...]}`。`fos channels run` 进程到点给每个收报人单聊发一张卡片（各自按自己的权限出报告）。每次推送记一条 Trigger（`source=schedule`，`external_id=daily_report:<日期>`），唯一约束保证同一天只推一次；进程重启错过的不补发。也可以 `fos daily-report luneng --send` 手动 / cron 推送。

## 上线检查

`fos pilot-check <租户>` 只读，三级结果：

- ✗ **阻断**：配置不合法；数据库连不上或迁移不是最新；没有管理员；审批规则用到的角色没有人（审批会卡住）。
- ! **提醒**：`FOS_ENV` 不是 prod（模拟信道开着）；模型网关 / OCR 是模拟模式；IM 凭据没配；企业微信 / 飞书适配器还没做；用户没绑定 IM；主数据还没导入；库里有演示数据；工程知识库没有真实价格；日报没有收报人。
- ✓ 其余就绪项。

有 ✗ 时退出码为 1，可以放进部署脚本。
