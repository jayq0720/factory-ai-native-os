## 0. 前提与假设

| 项 | 说明 |
|---|---|
| 参考架构 | 需求中提到"之前发的阿里云和 DeepSeek 架构"，但在本仓库和项目记录中**没有找到这两份资料**。本方案按以下理解编写，拿到原始资料后再对齐：<br>• **阿里云架构**：云-边-端协同的工业智能架构（IoT 接入 → 边缘计算 → 数据中台 → 模型平台/百炼 → 行业应用）。<br>• **DeepSeek 架构**：MoE 大模型 + 高效推理（Prefill/Decode 分离、KV Cache 复用、专家并行），以及"推理模型做规划、小模型做执行"的分层用法。 |

| 小模型 | 小米 OCR 模型（具体型号待确认）为 OCR 首选，PaddleOCR 作为开源兜底；视觉检测用 YOLO / RT-DETR 系列；时序异常检测用轻量开源模型。 |
| 语言 | **Rust**：边缘网关、协议采集、事件总线、OS 内核服务、安全沙箱等对性能和可靠性要求高的部分。**Python**：Agent 编排、模型服务、RAG、数据分析、算法训练。 |
| 部署 | 默认**私有化/本地化部署**（工厂数据不出厂），云端大模型 API 作为可选增强；需支持离线运行。 |

## 1. 产品定位：什么是"工厂 AI Native OS"

不是再做一个 MES/SCADA，而是在现有工业系统之上加一层**以 Agent 为核心的操作系统**：

1. **统一感知**：把设备（PLC/传感器/相机）、业务系统（MES/ERP/WMS/QMS）、文档（图纸、SOP、质检单）统一接入，变成 Agent 可以读的"资源"。
2. **统一认知**：工厂知识图谱 + 向量知识库 + 实时时序数据，构成工厂的"世界模型"。
3. **统一行动**：所有能力（查数据、下工单、调参数、发告警）封装成**带权限的工具（Tool/MCP Server）**，由 Agent 调用，高风险动作必须人工确认。
4. **统一交互**：工人、班组长、工程师、厂长用自然语言（文字/语音/拍照）与系统交互，替代大量表单和菜单操作。

类比传统 OS：

| 传统 OS | 工厂 AI OS |
|---|---|
| 硬件驱动 | 工业协议驱动（OPC UA / Modbus / S7 / MQTT / 相机） |
| 文件系统 | 工厂数据底座（时序库 + 关系库 + 对象存储 + 向量库 + 图谱） |
| 进程调度 | Agent 运行时与任务调度（模型路由、算力调度） |
| 系统调用 | 工具层（MCP Servers），带权限与审计 |
| 应用 | 场景 Agent（质检、设备运维、排产、安全、知识问答…） |
| Shell / GUI | 自然语言交互终端（Web、移动端、产线大屏、语音） |

## 2. 总体架构

```
┌─────────────────────────────────────────────────────────────────────┐
│ L6 交互层   Web 控制台 │ 移动端/企业微信/钉钉/飞书 │ 产线大屏 │ 语音终端        │
├─────────────────────────────────────────────────────────────────────┤
│ L5 场景Agent 质检Agent │ 设备运维Agent │ 排产Agent │ 安全Agent │ 知识助手 │ 报表Agent │
├─────────────────────────────────────────────────────────────────────┤
│ L4 Agent OS 内核（Rust + Python）                                       │
│   任务规划/编排 │ 记忆(短期/长期) │ 工具注册中心(MCP) │ 权限/审批 │ 审计回放 │ 评测 │
├─────────────────────────────────────────────────────────────────────┤
│ L3 模型层   模型网关(路由/限流/计费/缓存)                                    │
│   大模型: DeepSeek V3/R1 │ Qwen3 / Qwen-VL │ Seedance(视频)                  │
│   小模型: 小米OCR / PaddleOCR │ YOLO/RT-DETR │ 时序异常检测 │ Embedding/Rerank │
├─────────────────────────────────────────────────────────────────────┤
│ L2 数据与知识层                                                         │
│   时序库 │ 关系库 │ 对象存储 │ 向量库 │ 知识图谱(设备-工艺-物料-缺陷) │ 数据血缘     │
├─────────────────────────────────────────────────────────────────────┤
│ L1 接入层（边缘，Rust）                                                  │
│   协议驱动(OPC UA/Modbus/S7/MQTT) │ 相机采集 │ 边缘推理 │ 断网缓存 │ 系统集成(MES/ERP) │
├─────────────────────────────────────────────────────────────────────┤
│ L0 基础设施  K8s/K3s + KubeEdge │ GPU 推理节点 │ 网络隔离(OT/IT) │ 监控 │ 身份认证      │
└─────────────────────────────────────────────────────────────────────┘
```

**云-边-端划分**（对应阿里云的云边协同思路）：

- **端**：PLC、传感器、工业相机、扫码枪、工位平板。
- **边（车间级）**：Rust 边缘网关 + 小模型推理（OCR、视觉检测、异常检测），保证毫秒~百毫秒级响应和断网可用。
- **厂级中心（私有云）**：数据底座、Agent 内核、DeepSeek/Qwen 私有化推理集群。
- **公有云（可选）**：调用 DeepSeek / 通义千问 / 火山引擎（Seedance）API 做弹性补充、Seedance 视频生成、模型微调训练。

**模型分层调用原则**（借鉴 DeepSeek "大模型规划、小模型执行"）：

1. 实时链路（< 200ms）：只用边缘小模型和规则，不调大模型。
2. 交互链路（1–5s）：Qwen3 中等尺寸 / DeepSeek-V3 做对话、工具调用。
3. 深度链路（分钟级）：DeepSeek-R1 做根因分析、排产优化方案、复杂报告。
4. 内容生成链路（异步）：Seedance 生成 SOP 培训视频、事故复盘动画。

## 3. 模块设计与技术选型

### 3.1 L1 接入层 · 边缘网关 `fos-edge`（Rust）

| 功能 | 方案 | 可复用开源 |
|---|---|---|
| OPC UA 采集 | Rust 客户端 | `async-opcua`（原 `opcua` crate） |
| Modbus TCP/RTU | Rust | `tokio-modbus` |
| 西门子 S7 | 优先通过 OPC UA；必要时 FFI 封装 | `snap7`（C 库） |
| MQTT | 边缘内置 Broker + 上行桥接 | `rumqtt`（Rust）、NanoMQ / EMQX |
| 断网缓存 | 本地 WAL + 补传 | `sled` / RocksDB |
| 边缘推理 | ONNX Runtime 调用小模型 | `ort` crate、OpenVINO |
| 规则引擎 | 阈值/联锁规则，毫秒级响应 | 自研轻量 DSL 或 `rhai` 脚本 |
| 统一数据模型 | 设备点位 → 统一 Tag 模型（参考 OPC UA 信息模型 / 资产管理壳 AAS） | — |

输出：统一的事件流（Protobuf/JSON over MQTT 或 NATS），进入 L2。

### 3.2 L2 数据与知识层

| 类型 | 推荐 | 备注 |
|---|---|---|
| 消息/事件总线 | **NATS JetStream**（轻量）或 Redpanda/Kafka（大数据量） | |
| 时序库 | **GreptimeDB**（Rust 编写）或 TDengine / Apache IoTDB | 设备点位、工艺参数 |
| 关系库 | PostgreSQL | 工单、物料、人员、权限 |
| 对象存储 | MinIO | 图片、视频、图纸、文档 |
| 向量库 | **Qdrant**（Rust）或 Milvus | RAG 检索 |
| 知识图谱 | NebulaGraph / Neo4j | 设备-部件-故障-工艺-物料关系 |
| 文档解析 | RAGFlow / MinerU + OCR | 解析图纸、SOP、手册、质检报告 |
| 数据集成 | Apache SeaTunnel / Airbyte | 对接 MES/ERP/WMS |

### 3.3 L3 模型层 · 模型网关 `fos-model-gateway`

- **网关**：统一 OpenAI 兼容接口；路由、负载均衡、限流、Token 计量、语义缓存、敏感数据脱敏。可基于 **LiteLLM** 或 **Higress（阿里开源 AI 网关）**，核心路由逻辑后期可用 Rust 重写。
- **私有化推理**：**vLLM** / **SGLang**（SGLang 对 DeepSeek MoE 支持较好）；国产卡可评估昇腾 MindIE。
- **模型清单（初版）**：

| 用途 | 首选 | 备选 |
|---|---|---|
| 通用对话 + 工具调用 | DeepSeek-V3 系列 | Qwen3（中等尺寸可单机部署） |
| 复杂推理 / 根因分析 / 排产 | DeepSeek-R1 系列 | Qwen3 Thinking 模式 |
| 图像理解（缺陷描述、仪表读数、图纸问答） | Qwen-VL 系列 | — |
| OCR（铭牌、标签、单据、仪表） | 小米 OCR（型号待确认） | PaddleOCR、GOT-OCR2 |
| 目标检测（缺陷、安全帽、越界） | YOLO 系列 / RT-DETR | 注意 Ultralytics YOLO 为 AGPL，商用需评估许可，可优先 RT-DETR（Apache 2.0） |
| Embedding / Rerank | Qwen3-Embedding / Reranker | BGE-M3 |
| 时序异常检测 | Isolation Forest / LSTM-AE 等轻量模型 | Chronos、TimesFM 等时序基础模型 |
| 视频生成 | Seedance（火山引擎 API） | — |
| 语音 | SenseVoice / Paraformer（ASR）、CosyVoice（TTS） | 车间噪声环境需实测 |

- **微调**：LLaMA-Factory / ms-swift 做行业领域 LoRA 微调（工艺术语、缺陷描述、工单格式）。

### 3.4 L4 Agent OS 内核 `fos-kernel`

这是项目的核心自研部分。

| 子模块 | 语言 | 说明 | 可复用开源 |
|---|---|---|---|
| 工具注册中心 | Rust | 所有能力以 **MCP Server** 形式注册；包含 schema、权限等级、风险等级 | MCP 官方 Rust/Python SDK |
| Agent 编排 | Python | 多 Agent 编排、状态机、人在回路 | **LangGraph**（推荐）或 AgentScope（阿里开源） |
| 任务调度 | Rust | 长任务、定时任务、重试、补偿 | Temporal 或自研 |
| 记忆 | Python | 会话记忆、工厂长期记忆（经验案例库） | Mem0 思路 + 向量库 |
| 权限与审批 | Rust | RBAC + 工具级权限；L0 只读 / L1 低风险写 / L2 需审批 / L3 禁止 Agent 直接执行（如改 PLC 控制参数） | Keycloak（身份）、OPA/Cedar（策略） |
| 审计与回放 | Rust | 每次 Agent 决策、工具调用全量记录，可回放 | OpenTelemetry |
| 评测 | Python | 场景测试集、回归评测、幻觉检测 | Langfuse / Ragas |
| 低代码编排（可选） | — | 给工程师自己拼工作流 | Dify（可直接部署对接模型网关） |

**安全红线**：Agent **不允许直接写 PLC 控制量**；对 OT 侧的任何写操作必须走"建议 → 人工确认 → 网关执行 → 回读校验"流程，OT/IT 网络隔离，单向数据流优先。

### 3.5 L5 首批场景 Agent（MVP 选 3 个）

| 优先级 | 场景 | 用到的模型 | 价值 |
|---|---|---|---|
| P0 | **工厂知识助手**：SOP、设备手册、工艺文件问答，拍照问故障 | Qwen3/DeepSeek-V3 + RAG + Qwen-VL + OCR | 最快见效，验证数据底座和 RAG |
| P0 | **设备运维 Agent**：异常检测 → 自动拉取历史数据和维修记录 → 给出根因与处理建议 → 生成维修工单 | 异常检测小模型 + DeepSeek-R1 + 知识图谱 | 验证"感知-认知-行动"闭环 |
| P0 | **视觉质检 Agent**：OCR 读码/标签核对 + 缺陷检测 + 缺陷自动归因与统计报告 | 小米 OCR/PaddleOCR + YOLO/RT-DETR + Qwen-VL | 边缘推理链路验证 |
| P1 | 生产日报/周报 Agent | DeepSeek-V3 | 低风险、高频 |
| P1 | 安全巡检 Agent（安全帽、区域闯入） | 检测小模型 | |
| P2 | 排产优化 Agent | DeepSeek-R1 + OR-Tools 求解器 | 需与 MES/ERP 深度集成，放第二期 |
| P2 | SOP 培训视频生成 | Seedance | 内容生成类，异步 |

### 3.6 L6 交互层

- Web 控制台：React/Next.js（或 Vue，按团队习惯），包含对话、Agent 管理、工具/权限管理、审计回放、看板。
- 移动/IM：企业微信 / 钉钉 / 飞书机器人接入（工人不必装新 App）。
- 产线大屏、工位平板：精简对话 + 拍照 + 语音。

## 4. 代码仓库结构（建议 Monorepo）

```
factory-ai-native-os/
├── crates/                    # Rust
│   ├── fos-edge/              # 边缘网关：协议驱动、断网缓存、边缘推理
│   ├── fos-protocol/          # 统一数据模型 / Protobuf 定义
│   ├── fos-kernel/            # 工具注册中心、权限、审计、调度
│   └── fos-model-gateway/     # 模型路由（二期由 Python 版迁移）
├── services/                  # Python
│   ├── agent-runtime/         # LangGraph 编排、记忆
│   ├── agents/                # 各场景 Agent
│   ├── mcp-servers/           # 各业务系统/数据源的 MCP Server
│   ├── rag/                   # 文档解析、索引、检索
│   └── vision/                # OCR、检测模型推理与训练脚本
├── web/                       # 前端控制台
├── deploy/                    # Helm charts、docker-compose、K3s/KubeEdge 配置
├── evals/                     # 场景评测集
└── docs/                      # 架构文档、ADR
```

工程规范：Rust 用 `cargo workspace` + `clippy` + `cargo-deny`（许可证检查）；Python 用 `uv` + `ruff` + `pytest`；接口优先 gRPC/Protobuf，对外 REST/OpenAI 兼容；CI 用 GitHub Actions。

## 5. 三个月分阶段路线图

总时长 13 周，按 **2 周一个迭代**，每阶段结束有可演示的里程碑。

### 阶段一：基础底座（第 1–4 周）

| 周 | 任务 | 交付物 |
|---|---|---|
| W1 | 需求调研：选定试点产线，梳理设备清单、点位表、业务系统接口、文档资料；确认参考架构资料；搭建仓库、CI、开发环境 | 试点范围说明、点位表、ADR-001 架构决策 |
| W2 | 基础设施：K3s 集群、GPU 节点、MinIO、PostgreSQL、时序库、NATS、Qdrant 部署；Keycloak 统一身份 | 一键部署脚本（docker-compose + Helm） |
| W3 | `fos-edge` v0.1：OPC UA + Modbus 采集、MQTT/NATS 上行、断网缓存；模型网关 v0.1（LiteLLM/Higress）接入 DeepSeek、Qwen API | 试点产线实时数据入库；统一模型调用接口 |
| W4 | 私有化推理：vLLM/SGLang 部署 Qwen3（中等尺寸）+ Embedding；文档解析流水线（RAGFlow/MinerU + OCR） | **里程碑 M1**：数据可采、模型可调、文档可检索 |

### 阶段二：Agent 内核 + 首批场景（第 5–9 周）

| 周 | 任务 | 交付物 |
|---|---|---|
| W5 | `fos-kernel`：工具注册中心（MCP）、权限分级、审计日志；LangGraph Agent 运行时 | 内核 v0.1 |
| W6 | MCP Servers：时序数据查询、MES 工单、设备台账、知识库检索；**知识助手 Agent** 上线内测 | 知识助手可用 |
| W7 | 知识图谱 v0.1（设备-部件-故障-处理措施）；**设备运维 Agent**：异常检测 + 根因分析（DeepSeek-R1）+ 工单生成（人工确认） | 运维闭环 Demo |
| W8 | 视觉链路：边缘部署 OCR（小米 OCR / PaddleOCR）+ 缺陷检测模型；**视觉质检 Agent** | 质检 Demo |
| W9 | Web 控制台 v0.1（对话、审批、审计回放、看板）；企业微信/钉钉接入 | **里程碑 M2**：3 个场景 Agent 端到端跑通 |

### 阶段三：试点落地与加固（第 10–13 周）

| 周 | 任务 | 交付物 |
|---|---|---|
| W10 | 试点产线真实上线（影子模式：Agent 只给建议，不执行）；收集反馈、建立评测集 | 评测集 v1、问题清单 |
| W11 | 效果优化：RAG 调优、Prompt/工具优化、必要时 LoRA 微调；DeepSeek 私有化（视算力，量化版本）；语义缓存降本 | 准确率/响应时间报告 |
| W12 | 安全与稳定性：OT/IT 隔离验证、权限审计、压测、故障演练、监控告警（Prometheus + Grafana）；P1 场景（日报 Agent）；Seedance SOP 视频生成试点 | 安全评估报告 |
| W13 | 文档、运维手册、培训；验收演示；二期规划（排产、更多产线复制） | **里程碑 M3**：试点产线正式运行 + 可复制部署包 |

### 关键验收指标（建议，试点前与业务方确认）

- 数据接入：试点产线关键点位接入率 ≥ 95%，断网 30 分钟数据不丢。
- 知识助手：业务人员评测集回答可用率 ≥ 85%，P95 响应 < 5s。
- 设备运维：异常发现到给出处理建议 < 2 分钟；根因建议被工程师采纳率 ≥ 60%。
- 视觉质检：OCR 识别准确率 ≥ 98%（标签/铭牌）；缺陷检出率按产线标准定。
- 安全：所有写操作 100% 走审批与审计，Agent 无直接写 PLC 路径。
