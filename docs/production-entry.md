# 拍照录单与批次追溯（W9，里程碑 M1）

工人在 IM 里拍一张单据照片，系统识别后回一张录单卡片，点“确认”才入账；之后任何人发“追溯 批号”就能看到这个批次用了哪批原料、在哪一窑烧、检验结果如何。全程不调用大模型（识别用 OCR，取值、换算、查找都是确定性代码）。

## 一张照片怎么入账

```
照片 ──► OCR（Xiaomi-OCR-0 / Qwen-VL / 模拟）──► 认单据（detect 词，零模型）
     ──► 字段抽取（带页码和原文片段）──► 录单草稿（类型转换 + 查已有对象）
     ──► 录单卡片（L2）──► 点击人确认 ──► Ledger.append()（以点击人身份，证据 = 照片 + 页码片段）
```

- **认单据**：`packs/<pack>/extraction/entry_*.yaml` 里每份 Schema 有 `detect` 词，原文（和照片附带的文字）里出现次数最多的那份胜出；两份同分或都没出现就不猜，回“没有认出是哪种单据”，提示发照片时附一句单据名。
- **草稿**：`entry:` 段写明确认后追加哪个事件、每个事件字段取自哪个抽取字段（`fos/entry/spec.py`）。引用字段按编号或指定属性精确查找（物料按名称、原料批次按供方批号、窑次按窑次号），查不到、查到多个都会列为问题。真实单据不会匹配模拟对象。
- **卡片**：没有问题时带“确认 / 取消”按钮，需要该事件的写权限（如送货单需要 `warehouse.stock:write`），以点击人权限执行；有问题时不给按钮，列出问题，提示重拍或去控制台修改。
- **只入账一次**：幂等键 `entry:<文档>:<Schema>`。同一张照片重发会回“已经录过了”。
- **控制台**：文件类别选“生产/仓库单据”上传，或打开 IM 收到的照片，字段区上方有录单框；修改字段后自动重新核对，点“提交入账”以提交人身份写入（`POST /v1/documents/{id}/entry`）。命中审批规则（W8）时转为审批单。
- **模拟数据**：模拟 OCR 识别出的单据，事件也是模拟数据（`data_mode=mock`），不能导出正式文件。

### 行业包自带的五种单据（refractory）

| 单据 | Schema | 确认后的事件 |
|---|---|---|
| 原料送货单 | `entry_delivery_note` | `warehouse.lot_received` 来料入库（自动编号 `L<日期>-xxxx`，状态待检） |
| 生产任务单 / 配料单 | `entry_batch_start` | `production.batch_started` 批次开工（记下所用原料批次） |
| 装窑记录 | `entry_kiln_loading` | `production.batch_fired` 批次挂到窑次 |
| 报工单 / 出窑记录 | `entry_work_report` | `production.batch_completed` 合格数量、完工 |
| 理化检验报告 | `entry_inspection_report` | `quality.batch_inspection_recorded` 结论 + 指标一次录完 |

加一种单据：复制一份 YAML，改 `detect`、字段叫法和 `entry` 映射即可；启动时会对照本体检查映射（字段、引用、必填），不一致拒绝启动。现场拿到真实单据照片后，主要工作是给字段补叫法（labels）。

## 批次追溯

- IM：发 `追溯 B261106-01`（也可以是窑次号、原料供方批号、检验报告编号）。直接查引用图回一张卡片，不经过 Router，不调用模型。编号里没有数字的（如“追溯客户投诉”）仍交给 Agent。
- 控制台：右上角“批次追溯”。接口：`GET /v1/trace?q=编号`、`GET /v1/objects/{type}/{id}/trace/report`。
- 报告分三部分：**上游**（它用了什么：原料批次 → 物料 / 供应商，窑次 → 窑炉，产品）、**下游**（谁用了它：检验、用了这批原料的批次）、**关联**（上游对象的其他关联：来料检验、同一窑次 / 同一批原料的其他批次，排查影响范围）。
- 告警（检验不合格、来料判退 / 未检、烧成偏差……）、入口顺序、显示字段和枚举中文都在 `packs/<pack>/trace.yaml`，租户可在 `tenants/<id>/trace.yaml` 追加。
- 没有读权限的节点保留位置、隐去内容（“有关联记录，但你没有查看权限”）。报告带耗时，验收要求 10 秒内（本地 SQLite 约 10 ms）。

## 本地试一遍

```bash
.venv/bin/fos quickstart
.venv/bin/fos production-demo ./samples/production   # 登记模拟主数据（供应商、物料、产品、窑炉、窑次）+ 导出五张照片
.venv/bin/fos serve                                  # 打开 /app/，文件类别选“生产/仓库单据”，按 1–5 顺序上传并提交入账
```

或者走模拟信道（`POST /v1/channels/mock/messages`，见 `tests/test_entry.py`）：依次发五张照片、确认卡片，最后发“追溯 B261106-01”。

样例照片在 `packs/refractory/fixtures/entry/`，对应的模拟 OCR 结果按像素内容命名（`fixtures/ocr/px-<sha256>.md`）。改了单据内容后用 `.venv/bin/python -m fos.entry.samples` 重新生成。
